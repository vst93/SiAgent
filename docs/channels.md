# 聊天渠道

渠道接入由适配器、平台消息底座和 Agent 三部分组成。平台统一保存渠道配置、消息去重、会话映射、任务关联及投递状态；适配器负责消息平台的连接与协议，不拥有 Agent 引擎。配置页根据适配器声明生成字段。

当前内置：

| 适配器 | 适用入口 | 配置与网络 |
| --- | --- | --- |
| 企业微信 · 智能机器人 `wecom-bot` | 企微智能机器人的 API 长连接模式，推荐 | BotID、长连接 Secret；出站访问 `wss://openws.work.weixin.qq.com`，无需公网回调 |
| 企业微信 · 自建应用 `wecom-app` | 兼容原有企业内部应用 | CorpID、应用 AgentID、Secret、Token、EncodingAESKey；需公网 HTTPS 回调 |

两者是不同产品入口。用户提供的[接收消息文档](https://developer.work.weixin.qq.com/document/path/100719)属于智能机器人；旧的自建应用字段不能用于机器人配置。智能机器人还支持 URL 回调模式，本实现选择[官方长连接模式](https://developer.work.weixin.qq.com/document/path/101463)。当前不提供智能机器人 URL 回调适配器。

两种企微实现均作为随系统分发的渠道插件注册，核心通过统一接口管理配置、任务和投递。插件结构、Webhook 扩展和外部插件安装见 [渠道插件开发](channel-adapters.md)。已有渠道配置及回调 URL 无需调整。

## 连接企微智能机器人

1. 在企微智能机器人配置中开启 API 模式，选择“长连接”，取得 BotID 和该模式专用的 Secret。
2. 打开“配置 → 渠道接入 → 新增渠道”，保留“企业微信 · 智能机器人”，填写名称、BotID 和 Secret，选择 Agent。首次可先保持停用并保存。
3. 可点击“检查连接”，平台短暂建立连接、验证认证后关闭，不发业务消息。**同一机器人只能有一条有效长连接**，测试也可能替换其他工具的同机器人连接；迁移时先停用其他客户端。
4. 编辑配置，勾选“启用渠道”及模型服务数据确认，保存。检查连接状态是否为“已连接”。启用中的连接检查读取当前连接状态，不另开一条机器人连接。
5. 在企微与机器人单聊，或在群中 @ 机器人发送文字。查看实际回复，并在渠道页核对最近入站、任务会话和发送状态。

修改名称不会重建连接。连接标识保存后固定；更换账号或机器人应新增渠道。修改连接参数、密钥或 Agent 绑定前先停用；密钥留空保留，不回显。归档会解绑 Agent 并停止尚未发送的消息，保留历史；归档后重新创建同一标识会产生独立渠道与会话。

只有启用并明确绑定的渠道才接收新消息。Agent 任务提交时复用平台原有模型、指令、工具和知识库授权快照，不将这些凭据交给渠道适配器。

## 消息与会话范围

当前企微机器人适配器接收文本、图片、图文混排和语音转写内容的单聊与群内 @ 消息。语音使用官方转写文本；视频、文件等其余类型返回文字范围说明，不下载附件。智能助理、频道等 `compat_info` 扩展来源暂不接收，不据此创建普通用户会话。

### 图片消息

图片需要同时满足三个条件才会进入 Agent：渠道适配器的声明里包含 `images: true`（当前为企微智能机器人）、绑定 Agent 的“允许渠道成员发送图片”开关为开启（默认开启）、主模型在模型连接中勾选了图片输入。任一条件不满足时，成员收到明确的文字说明，消息记为 `rejected`，不创建任务；管理后台的入站记录能看到原因。

满足条件时的处理链路：

1. 适配器用 SDK 下载并按消息自带的 AES 密钥解密图片，只把暂存文件名写进私有协议。图片不会放进协议帧——单帧上限 256 KiB，而单张图片允许 4 MiB。
2. 平台按内容（不是文件名）检测格式，只接受 PNG/JPEG/WebP/GIF，并套用与 Web 附件相同的单张 4 MiB、单条 5 MiB、最多 8 张限制。超限或格式不符时记为 `rejected` 并删除已上传文件。
3. 通过校验的图片暂存在 `<data>/channel-media/<channel>/staged/`，入站记录保存暂存清单。任务准入时转成该会话的普通对话附件，与 Web 上传的附件完全同构，所以管理后台的会话历史会直接显示图片，模型也按 image content block 收到。
4. 只有文字、没有图片的图文混排按文本处理；只有图片没有文字时，平台补一句“请查看图片。”作为本轮提问，不臆造成员未发送的内容。

图片属于业务数据，和文本一样随会话保存在平台 SQLite 与附件目录中。清理渠道会话会一并删除附件文件；服务重启时所有未准入的暂存图片都会被清除，因为待处理入站消息在重启后本就不会恢复。归档渠道同样清除其暂存目录。

Agent 可限制私聊/群聊，并选择群内按成员隔离或全群共享。默认不同成员不共享；无论何种范围，不同群、群与私聊、不同渠道及 Agent 仍隔离。可配置空闲后开启新会话和是否允许用户 `/new`，完整策略见 [Agent 策略说明](agent-policy.md)。`/new` 可重置后续会话。命令前允许有一个 @ 提及前缀（企微群消息会保留该前缀），例如 `@机器人 /new`；其余带前缀的文本不被当作命令。

渠道会话在 Web 中保持只读，可查看、取消或按平台规则清理；不能从 Web 注入成员消息。消息和模型结果作为业务数据保存在 SQLite，不写入普通日志。

官方 SDK 负责认证、心跳和网络断线退避重连。认证失败限次停止；被同机器人另一连接替换时，不主动反复抢占。消息先写入平台入站记录，再复用原 FIFO 调度。消息 ID 在渠道作用域内排重，冲突内容拒绝。重复回调中变化的传输请求 ID不创建新任务；在尚未发生外部发送时可更新回复上下文。

支持原地更新消息的适配器（当前为企微智能机器人）在启用 Agent 的“立即确认”后，收到消息即发送一条“已收到，正在作答”的确认，通常 1 秒内可见。模型开始输出后，平台按约 1.5 秒的最小间隔、且内容确有增长时更新同一条消息，任务完成时用完整回答覆盖；单条草稿按适配器字节上限截断，不会拆成多条。确认、作答进度、处理中提示和最终回复共用同一 `stream.id`：中间内容 `finish=false`，只有最终回复 `finish=true`。企微单条流式消息需在 10 分钟内结束，平台以 9 分钟为界切换新的流式消息，避免更新已过期消息。关闭“流式输出”后不再推送中间内容，只发送最终回复。

Agent 开启处理中提示时，消息排队超过 30 秒或已开始处理并超过 90 秒才发送一次提示；已经输出过作答进度时不再发送，避免旧文案覆盖新内容。关闭后不再发送任何中间提示。最终回复可按 Agent 配置附加思考摘要（受“思考摘要最多字符”限制）、工具状态或详情以及来源列表。自建应用等不支持原地更新的适配器不发送即时确认和草稿，只发送最终文本。普通回复仍受厂商 24 小时回复窗口约束。长回复按适配器字节限制分段，最多 64 段，超出部分明确提示。

### 会话列表与联系人标记

企微长连接协议只返回不透明的 `userid` 与 `chatid`，没有任何群名或成员名，SDK 也不提供查询接口。因此：

- 管理后台以“联系人”为单位展示，只保留两层：**联系人 → 会话**。

  - 联系人的身份由 Agent 的群聊范围决定：“按群内成员隔离”时每个成员是一个联系人（名称下方标注所属群），“全群共享”时群本身是一个联系人（标注“全群共享”）。
  - 列表按最近活动排序，每行显示名称、所属群/私聊、会话数和最近时间；只有当前选中的联系人才展开它的会话，避免一屏堆满所有会话。
  - 会话按最近活动倒序，标注“第 N 次”“N 问”和相对时间。空闲重置或 `/new` 之后的会话就是这样区分开的。
  - 顶部可按“全部 / 群聊 / 私聊”过滤。渠道名不单独占一层，因为同一个 Agent 通常只绑定一个渠道。
  - 详情头部显示完整路径（渠道 · 群聊 · 群名 · 成员）以及“第 N / 总数 次会话”。
- 未标记时直接显示原始 ID（“未命名群”“未命名成员”）。在分组标题上点编辑按钮可设置名称，保存后作用于该群或成员的全部会话。标记按渠道与 ID 存储，重命名不会改写历史消息。
- 渠道诊断的“最近入站消息”同样显示标记后的群名与成员名，便于对照是谁发来的。

成员也可以自己标记名称，命令在创建任务之前处理，不会调用模型：

| 命令 | 作用 |
| --- | --- |
| `/user 张三` | 标记发送者自己的名称，作用于该渠道下的这个成员 |
| `/group 产品讨论群` | 标记当前群的名称，仅群聊可用 |

重复发送以最后一次为准。管理后台保存的名称会覆盖成员设置，并记录来源（“成员设置”标记）。命令前允许一个 @ 提及前缀；名称不超过 64 字、单行。命令由 Agent 策略“允许成员用 /user 和 /group 命令标记名称”控制，默认开启；关闭后命令只收到说明。

会话列表按**最近一次消息时间**排序，而不是创建时间：活跃的群会话会升到顶部。管理后台每 5 秒静默刷新一次列表，因为渠道消息来自其他客户端；当前打开的会话仍由 SSE 推送更新，不依赖轮询。

会话详情默认只加载最近 40 条消息（约 20 轮问答）。向上滚动到顶部时加载更早一页，游标是当前最早消息的 ID，加载后保持阅读位置不跳动。分页只影响展示，完整记录仍保存在平台数据库中。

## 投递与恢复

发送前先持久化 `sending`；只有平台收到适配器对厂商成功回执的确认，才记录 `sent`。这表示渠道接受，不表示成员已读或保证端到端送达。

- `pending`：尚未尝试。
- `retry`：尚未连接或被厂商明确以可重试错误拒绝；最多 3 次，间隔 2、5 秒。
- `failed`：明确拒绝或达到重试上限，可手动重试发送，不重跑 Agent。
- `unknown`：超时、断线或确认前进程退出，结果不明，不自动重发，也不提供直接重试按钮。
- `blocked`：同一回复前面的分段未确认成功，停止后续分段。
- `cancelled`：渠道归档，或确认/作答进度已被最终回复取代。

SDK 重连只恢复连接和订阅，不重放业务发送。官方 SDK 的请求队列在断开时被清理，平台也不会重新调度未知出站。服务重启会将发送中记录标记为结果不明；未完成 Agent 任务按原规则中断，不重跑。仅落盘未创建任务的旧入站产生重新发送说明，不静默恢复旧任务。

平台持久化保证从入站成功提交开始。WebSocket 推送与平台 SQLite 之间没有厂商提供的跨系统事务；不能承诺平台接收前的消息绝不丢失。适配器收到落盘拒绝时会停止连接，避免继续接受未能保存的消息。

清理已结束会话会移除正文、会话关联和回复上下文中的成员/群/请求标识，保留最小去重墓碑。旧重复消息不会重新填入这些个人数据。

## 扩展与依赖选择

内置机器人直接依赖官方 **`@wecom/aibot-node-sdk@1.0.7`**，npm 元数据标注 MIT；随 `make install`、容器构建安装，无需管理员另装 OpenClaw。源码及协议参考：

- [官方 Node SDK](https://github.com/WecomTeam/aibot-node-sdk)
- [官方长连接说明](https://developer.work.weixin.qq.com/document/path/101463)
- [智能机器人接收消息](https://developer.work.weixin.qq.com/document/path/100719)
- [企微团队 OpenClaw 插件](https://github.com/WecomTeam/wecom-openclaw-plugin)
- [社区 OpenClaw 企微插件](https://github.com/sunnoy/openclaw-plugin-wecom)

OpenClaw 插件需要其插件运行接口，不能作为 SiAgent 的同名包直接安装即用。这里复用独立官方传输 SDK，避免引入第二套会话与 Agent 运行机制。其他项目的连接器若可独立使用，可通过薄适配进程接入；安装和协议见 [channel-adapters.md](channel-adapters.md)。本次未复制社区插件实现。

## API、迁移与验证

统一管理 API：

| 接口 | 作用 |
| --- | --- |
| `GET /api/channel-providers` | 已安装适配器与配置字段 |
| `GET/POST /api/channels` | 列表、新建 |
| `PUT/DELETE /api/channels/{id}` | 编辑、归档 |
| `POST /api/channels/{id}/test` | 检查连接或短暂认证测试 |
| `GET /api/channels/{id}/diagnostics` | 最近入站、出站及连接状态 |
| `GET /api/channel-contacts` | 渠道联系人标记（可按 `channel_id` 过滤） |
| `PUT /api/channel-contacts` | 设置群或成员名称，`name` 为空表示清除 |
| `DELETE /api/channel-contacts` | 删除标记 |
| `POST /api/channel-deliveries/{id}/retry` | 仅重试明确失败的投递 |

这些管理接口全部要求登录和写操作 CSRF。旧 `/api/wecom/*` 及 `/callbacks/wecom/{id}` 保留给兼容适配器；详见 [wecom.md](wecom.md)。

schema **9** 将原企微表迁移为 `channels`、`channel_sessions`、`channel_inbox`、`channel_outbox`，原企业/应用标识转为 `wecom-app` 的配置。保留原渠道、会话、入站、任务及出站 ID、密文和永久会话来源。升级前停止整个服务并备份完整数据目录；旧程序不能打开版本 9，回退须恢复升级前完整备份。

本地测试覆盖官方 SDK 的真实 WebSocket 认证/消息/回执、单聊/群范围隔离、稳定流式 ID、明确拒绝与未知发送、重连不重放；也覆盖安装独立适配器、通用配置、密钥保留/脱敏、平台调度/投递、schema 1–8 迁移和旧自建应用进程链路。浏览器覆盖默认机器人表单、兼容应用、只读标识、空密钥保留及 320/390px 布局。

真实 BotID/Secret、企微网络与成员实际收发仍需真实环境验收；本地协议服务通过不等同于真实企微已接通。
