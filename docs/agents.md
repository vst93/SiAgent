# 多模型与助手管理

顶部“配置”提供独立的“模型连接”和“Agent”栏目，桌面与移动端使用同一套导航。模型连接统一维护地址和凭据，Agent 负责角色、模型选择及能力授权。首次使用只需保存一个模型，平台自动创建默认助手。页面切换和默认页设置见 [workspaces.md](workspaces.md)。

## 操作与边界

1. 在“配置 → 模型连接”新增 OpenAI Chat Completions 兼容连接，保存后可单独测试。连接的服务地址、模型名称、协议、上下文、输出、推理/采样参数、密钥和配置版本分别保存（见 [模型配置](models.md)）；编辑时留空密钥只保留该连接自己的密钥。
2. 在“配置 → Agent”新建助手，选择已保存的模型，设置名称、角色指令和是否接收新任务。多个助手可以共用一个模型连接，也可以使用不同连接。
3. 在“Agent 对话”的助手选择器选择目标，或在 Agent 配置列表点击“进入对话”；会话列表只展示该助手的历史。“新对话”固定归属于所选助手，已有会话没有改绑接口。
4. 在 Agent 编辑器的“工具授权”逐项选择 Skills/MCP；在“知识库关联”确认并保存资料范围。Skills 的上传/文件浏览/归档及 MCP 的编辑/连接测试/归档分别位于独立页签，统一入口为“配置 → 插件接入”，文档统一位于“配置 → 知识库”。新助手默认没有技能、MCP 或知识库权限，不复制默认助手授权。
5. 停用后不接收新对话和新消息，已有队列继续处理，可在相应会话单独取消。
6. 归档前先保存停用状态。归档后保留助手、能力关联和会话历史，不能修改配置或继续提问。当前不提供恢复归档操作。默认助手和默认模型连接保留，可以编辑或停用助手。

修改模型连接会影响所有使用它的助手之后提交的任务。每个任务在提交时独立冻结模型连接/版本、加密凭据、助手指令、能力定义及知识库范围，因此修改、停用或归档不改变已经接收的任务。知识库查询仍读取当时已发布的文档，已删除资料立即退出新检索。

归档模型连接前，所有未归档助手必须先改用其他模型或归档。归档 Skills/MCP 时同样核对所有未归档助手，而非只检查当前助手。归档保留历史运行和冻结配置需要的记录及文件。

助手间的对话上下文按不可变会话 ID 隔离；每次运行使用各自的模型集合和工具注册表。本地 MCP 工作目录为 `<data>/workspaces/<agent_id>/`，这仍不是操作系统沙箱。所有管理操作由同一个管理员负责；助手选择不构成多用户权限系统。

## 数据与迁移

多模型/助手在 schema **5** 引入，平台当前 schema **9**，自动从版本 1–8 迁移。多模型阶段新增：

- `models.id` 可容纳多个连接，增加 `archived`；迁移保留原连接 ID 1、密文和版本。
- `agents.model_id` 指向所选连接，增加 `archived`；原默认助手关联模型 1。
- `conversations.agent_id` 固定会话归属；历史会话迁移为默认助手。
- 新运行配置保存 `model_id` 和完整助手快照，旧运行继续按其原快照读取。

工具和知识库沿用现有 `agent_capabilities`、`knowledge_bindings`；没有新增调度器或 Agent 引擎。模型选择、存在性和归档状态由 Go 管理 API 校验，运行也从会话归属重新读取助手，不接受客户端在发消息时另传一个助手以改绑。

升级前停机备份整个数据目录。迁移后回退需恢复完整旧备份。已测试旧认证、模型密钥、消息、工具、知识库索引/绑定、解析原文及来源记录保留。

## API

均复用现有管理员认证、CSRF 和来源校验。

| 方法与路径 | 作用 |
| --- | --- |
| `GET/POST /api/models` | 模型连接列表/创建；列表不返回密钥 |
| `PUT /api/models/{model}` | 更新指定连接，留空密钥只保留该连接的原密钥 |
| `POST /api/models/{model}/test` | 测试指定已保存连接 |
| `DELETE /api/models/{model}` | 校验关联后归档非默认连接 |
| `GET/POST /api/agents` | 助手列表（含归档记录）/创建 |
| `GET/PUT/DELETE /api/agents/{agent}` | 读取/编辑/校验后归档 |
| `GET/PUT /api/agents/{agent}/capabilities` | 指定助手的 Skills/MCP 授权 |
| `GET/PUT /api/agents/{agent}/knowledge` | 指定助手的知识库绑定 |
| `POST /api/conversations` | 可传 `{"agent_id":"..."}`，省略时仍使用默认助手 |

`/api/model`、`/api/model/test` 和 `/api/agent` 系列保留为默认资源的兼容入口。运行详情新增提交时的助手标识、名称及模型连接标识，方便区分同名模型。

## 验证和后续渠道集成

Go 测试覆盖连接密钥隔离、配置版本、权限、归档约束、全助手资源引用检查、会话不可改绑、排队配置冻结及 schema 1/2/3/4 → 5。完整 Go/Node 测试验证指定模型执行、无默认权限继承、上下文隔离、归档和服务重启后的历史；Chromium 验证创建、切换、单独连接测试、来源范围、停用归档及桌面/390px 布局。

企业微信内部应用现已按渠道配置路由到指定助手，成员会话按应用/成员/助手隔离；助手归档校验包含所有未归档渠道（含停用渠道），须先解绑或归档渠道。schema 6 保留 schema 5 多模型/助手数据，并为渠道会话保存永久来源，Web 可查看/取消任务或显式清理历史，新消息仍须来自渠道回调。配置和投递规则见 [wecom.md](wecom.md)；真实企业验收仍需企业应用、内部成员和 HTTPS 环境。
