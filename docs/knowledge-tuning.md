# 知识库切片与检索摘要

当前为本地 gse 分词 + SQLite FTS5/BM25 检索。按页、空白行段落保留位置，先匹配全部有效查询词，再在无结果时回退为任一词匹配。它适合小规模制度、手册和业务资料的关键词检索。

## 本轮调整

| 项目 | 原来 | 当前 |
| --- | --- | --- |
| 长段窗口 | 最长 1000 个 Unicode 字符，直接截断 | 最长 600 字符；优先在 360–600 字符之间沿句末或换行切分，其次寻找词间空白 |
| 相邻窗口重叠 | 150 字符 | 80 字符，保留连续覆盖与真实字符坐标 |
| 检索测试摘要 | 最多 600 字符 | 查询有效分词不超过 2 个时最多 140 字符，其余最多 220 字符；省略号另计 |
| 摘要选窗 | 围绕最早出现的词 | 在查询词周围比较候选窗口，优先覆盖更多不同查询词 |
| Agent 检索摘要 | 最多 600 字符 | 保留 600 字符预算，不使用管理测试的紧凑摘要 |
| 原文读取 | 不可变版本的完整片段与分页原文 | 保留完整来源，不以紧凑摘要覆盖原文 |
| 写入索引 | 逐片段重复执行 SQL | 发布事务内复用 prepared statements，原子切换与失败保护保持 |

短段落直接保留，不跨页或跨段合并。段落分隔正则只编译一次。英文小数中的点不作为句末边界；没有合适边界时使用字符上限。这里的切分仍基于结构和标点，不承诺语义理解。

更细的分片会增加索引行数，可能改变 BM25 排序。它不保证所有查询都比大分片更好；尤其跨段问题、同义表达和泛化单词，需要实际业务资料验证。检索测试的摘要缩短不等于检索范围缩小，也不会改写来源位置。

## 已有文档

紧凑摘要立即作用于已有索引。新的 600/80 切片规则只作用于新上传、替换、重新索引时生成的版本。

已有文档在“文档管理 → 行末 ••• → 重新索引”应用新规则。新版本处理成功后原子切换，失败时继续使用原版本；历史对话来源仍指向原来的不可变版本。不批量改写已发布片段，不自动重建所有资料。

## 本地基准

命令：

```sh
go test ./internal/knowledge -run '^$' -bench BenchmarkKnowledge -benchtime=3x -count=3
```

环境为本机 Darwin/arm64、Apple M5，单连接 SQLite 测试库。语料为 44,800 个中文字符的重复规则文本，检索词“发票”，最多返回 5 个结果；每组 3 次采样，每次 3 次迭代。以下取采样中位数：

| 指标 | 调整前 | 调整后 |
| --- | --- | --- |
| 上传与索引耗时 | 27.163 ms/op | 26.216 ms/op |
| 上传与索引分配内存 | 23,786,629 B/op | 20,923,040 B/op |
| 检索耗时 | 0.292 ms/op | 0.263 ms/op |
| 检索分配内存 | 64,914 B/op | 30,994 B/op |

这个小样显示本次调整没有以明显性能退化换取更小片段，检索分配内存约减少 52%。它不代表真实生产 WAL、并发、多文档、不同语言或真实问答的质量评测。基准代码保留在 `internal/knowledge/performance_test.go`，后续可用实际语料继续测量。

行为测试覆盖句子边界、英文小数、字符坐标、80 字符重叠、无丢字、取消、多查询词摘要覆盖、完整来源读取，以及管理摘要不缩减 Agent 检索上下文。原有原子发布、历史版本、删除隔离、中英文检索和 PDF 测试继续运行。
