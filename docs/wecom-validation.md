# 企业微信内部自建应用：验证记录

**状态：未完成真实联调。** 当前没有测试企业的应用配置、内部成员和公网 HTTPS 回调环境。配置、回调、去重、成员路由及异步发送已实现并通过本地协议/真实 Runtime 测试；本地证据不能代替企业实际验收。

范围只包含企业微信内部自建应用的文本私聊，不包含微信客服、外部联系人、群聊、图片或语音。

## 真实验证所需条件

- 可管理的企业及自建应用，准备 CorpID、AgentID、Secret、回调 Token、EncodingAESKey。
- 至少一名在应用可见范围内的内部测试成员，能够进入应用并发送消息。
- 可被企业微信访问的 HTTPS 回调域名及证书；服务器可访问企业微信接口。部署前需核对当前企业/应用的可信域名、可信 IP 等平台要求。
- 回调服务按官方协议校验签名、解密 URL 验证请求和消息，不把消息明文或 Secret 写入普通日志。

文档入口：[企业微信开发者中心](https://developer.work.weixin.qq.com/document/)。本地实现已经核对加密、接收、获取 token、发送和全局错误码的官方文档，来源链接、采用的限制及错误分类见 [wecom.md](wecom.md)。实际联调仍须复核当时的权限、频率和网络要求。

## 本地实现证据（不计作真实企业验收）

- Go 单元/竞态测试覆盖加密与应用接收身份、签名、并发去重、成员会话、`/new`、等待提示、分段、限次退避、明确失败单独重试、未知状态阻断、重启恢复及归档约束。
- `TestWecomCompleteLocalRuntimePath` 经真实 Node/Pi Durable 子进程请求本地模型协议服务，并将输出投递到本地企微协议服务；两次相同回调只执行一次模型调用。
- Chromium 使用独立 Node crypto 生成加密 echostr，在无管理员 Cookie 条件下经实际 Go HTTP 入口验证回调 URL；覆盖配置保存、密钥不回显和桌面/390px 页面。
- schema 5 → 6 明确测试多模型密钥、助手及既有会话归属保留；更早 schema 迁移链继续回归。

真实企业条件具备后，按上方清单逐项补充实际成员收到消息的脱敏证据，不能仅凭 access_token、`errcode=0` 或本地截图勾选通过。
