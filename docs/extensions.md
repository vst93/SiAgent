# 扩展包

扩展包扩展平台能力，与 Skills/MCP 分开：Skills/MCP 是给模型使用的工具，扩展包是给平台增加解析等能力的本地程序。当前只支持 `parser` 类型；模型供应商以“供应商扩展”的形式在模型连接页启用，渠道适配器随系统分发并在渠道页管理。

## 安装布局

```text
<data>/plugin-packages/<id>/<version>/
  plugin.json
  parse.sh          # 可执行入口
```

`plugin.json`：

```json
{
  "schema": "siagent.plugin/v1",
  "id": "acme.parser",
  "name": "Acme Parser",
  "version": "1.0.0",
  "type": "parser",
  "api_version": "1",
  "entry": "parse.sh",
  "description": "解析 .xyz 文件",
  "extensions": [".xyz"],
  "timeout_ms": 5000
}
```

约束：

- `id` 为小写字母、数字、点和连字符，2–64 字节；`version` 为 1–3 段数字，可带后缀。
- `entry` 必须是包内普通文件且可执行；拒绝绝对路径、`..`、反斜杠和符号链接逃逸。
- `extensions` 必须是以点开头的 1–16 个扩展名。
- 清单最大 64 KB，扩展名最多 16 个。

## 生命周期

在“配置 → 扩展”中：

1. **发现**：页面列出 `plugin-packages` 下的所有版本。
2. **安装**：登记某个版本；升级时新版本替换当前记录，旧版本文件保留用于回滚。
3. **启用/停用**：只有启用的解析扩展才会接收上传。停用后对应格式立即被拒绝，已索引文档不受影响。
4. **回滚**：切换到同一扩展的另一个已安装版本。
5. **卸载**：移除登记，磁盘文件保留，可重新安装。
6. **事件**：安装、升级、启用、停用、回滚、卸载写入 `plugin_events`，页面显示最近 12 条。

所有操作写入管理员审计（`plugin.*`）。扩展启用/停用不需要重启服务。

## 解析扩展如何运行

上传扩展声明的格式时，Go 以 `entry <文件绝对路径>` 直接执行入口，不经过 Shell，工作目录为包目录，环境变量仅 `PATH` 与 `LANG`，输出上限 4 MB、超时 20 秒。标准输出作为提取文本，随后走与 TXT/PDF 相同的结构识别、切分和索引流程。

- 非零退出、超时或空输出会让该文档标记为失败，并给出可操作提示；平台和其他文档不受影响。
- 扩展以服务账户运行，属于**可信代码**，不是沙箱。只安装可信来源。
- 扩展无法访问平台数据库；它只收到一个文件路径。

## 安全边界

- 不下载依赖、不执行安装脚本；包必须自包含。
- 不向扩展传密钥；入口文件在安装时校验。
- 扩展崩溃只影响当前文档处理。
- 渠道适配器继续使用既有进程协议，在“渠道接入”中启停；扩展页只展示其分发状态并跳转配置。
