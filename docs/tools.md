# Skills 与 MCP

工具是可选能力。在“配置 → 插件接入”通过独立的 Skills/MCP 页签上传技能、编辑/测试/删除 MCP 服务；然后到“配置 → Agent”选择目标助手，在“工具授权”中逐项保存权限。插件接入页不授予任何 Agent 权限。未选择并保存的工具不会提供给助手，每个助手独立保存授权；新增助手默认不继承权限。多模型、归档和会话归属见 [agents.md](agents.md)。

## 上传与管理 Skills

在“Skills”页签点击“上传 Skill”，选择 ZIP 技能包、单个 `SKILL.md` 或本机文件夹，不需要填写服务器目录。文件夹根部必须包含 UTF-8 `SKILL.md`；ZIP 可直接包含该文件，也可包含一个顶层技能文件夹，或包含多个技能文件夹的集合：

```markdown
---
name: order-guide
description: 订单查询的处理指引。
compatibility: 参考 references/status.md；脚本依赖 Python 3。
---
先核对用户提供的订单号，再使用已授权的查询工具。
需要字段解释时读取 references/status.md。
```

`name` 为小写字母、数字和单连字符组成的标识，最长 64 字符；`description` 必填，最多 1024 字节。可选的 `compatibility` 展示依赖和运行环境，最多 2000 字节。管理页提供搜索、技能详情和文件目录树，可查看完整指令、依赖要求，预览脚本、requirements 等 UTF-8 文件；不会安装依赖或执行导入的脚本。`allowed-tools` 等额外 frontmatter 字段不会授予工具权限。

上传需要确认可信来源。Go 校验后为每次上传创建独立的 `<data>/skills/<id>/` 目录，保留包内相对路径，后续不依赖原文件夹。ZIP 最多 10 MiB；解包前后均受限，拒绝绝对路径、上级路径、重复路径和目录/文件冲突，忽略 Finder 的 `__MACOSX`、`.DS_Store` 元数据。目录内部不接受符号链接或特殊文件。单个技能最多 200 个文件、400 个目录项，单文件 2 MiB、总计 8 MiB；一次上传多个技能时最多 2000 个文件、4000 个目录项、总计 80 MiB。`SKILL.md` 最多 64,000 字节。保存的文件权限为 0600，目录为 0700。上传暂存位于平台数据目录内，成功或失败后清理，启动时清理上次中断的暂存；已登记的技能目录不受影响。

技能以 `SKILL.md` 中的 `name` 识别。未勾选“覆盖同名技能”时，上传同名技能会被拒绝；勾选后使用新文件替换旧技能，并保留原技能 ID 及所有 Agent 挂载关系。替换先写入暂存目录，成功后才切换，失败不会破坏已安装的技能。

技能详情提供“导出 ZIP”，压缩包根部即 `SKILL.md` 和资源文件；技能库提供“导出全部”，压缩包内每个技能位于以 `name` 命名的顶层文件夹。两者都可用“上传 Skill”重新导入；导出全部得到的压缩包会作为一个技能集合批量导入，勾选覆盖即可恢复或更新整库。

上传不会自动授权或挂载。进入“配置 → Agent → 工具授权”，在“Skills 挂载”勾选技能并确认保存。Skills/MCP 页签之间切换保留各自的浏览与编辑状态。Skills 详情支持内容预览、在线编辑并保存 `SKILL.md` 和文本资源；删除技能或 MCP 会在确认后自动从所有关联 Agent 移除，不再要求先手动解除关联。

关联后，指令和资源清单进入模型上下文。Runtime 通过 Pi Durable 的 `configure` / `defineExtension` / `defineTool` 注册能力；只有选中 Skill 才能通过 `skill_resource` 读取其清单中的资源。管理预览和单次资源读取仅支持 UTF-8 文本，最多 128 KB，不支持任意路径读取。资源是按需发送给当前模型服务的业务数据。超过上下文限制时提示新建会话，不静默截断指令。

默认只有 `skill_resource` 读取脚本文本，脚本不会自动执行。为 Agent 开启“本地工作区工具”后，模型会同时获得 `read` / `write` / `edit` / `bash`，Skill 目录的绝对路径也会作为只读参考写入上下文；需要运行 Skill 脚本时，应先把文件复制到 `<data>/workspaces/<agent>/` 再执行。Skill 正文里的指令不能自行开启工具，是否开放 Shell 始终由管理员在 Agent 设置中决定；未开启高级工具时，可改用可信 MCP 服务提供执行能力。

## 本地 stdio MCP

固定使用 MIT 许可证的 `@modelcontextprotocol/sdk@1.32.1`，负责初始化、能力协商、工具分页发现和调用。程序和参数数组分别保存，不拼接 Shell 命令。例如：

```text
程序：/usr/local/bin/node
参数：["/opt/trusted-mcp/server.mjs"]
环境变量：{"SERVICE_TOKEN":"由管理员填写"}
```

程序和脚本路径使用运行服务器可访问的绝对路径；Docker 内路径与宿主机不同。镜像内 Node 默认在 `/usr/local/bin/node`。所需依赖和可信程序需由管理员预先准备，平台不自动下载或安装 MCP 服务。

只向服务传入显式配置的环境变量；若程序需要 PATH、HOME 等，也需显式填写。操作系统自身可能添加少量变量，例如 macOS 的 `__CF_USER_TEXT_ENCODING`。密钥请放环境变量，**程序与参数按普通配置保存**。环境变量加密保存，不回显值；留空沿用已有配置，填写 `{}` 或选择清除已有值可移除配置。

SDK 默认 stdio transport 会继承部分环境变量，因此使用其 `Client`、`Transport` 接口和消息 framing/parser，增加精确环境的传输适配。独立 Node 守护进程启动 MCP 进程组，并保留与 Runtime 的 IPC 控制通道。正常关闭清理进程组；Runtime 被 SIGKILL 时，守护进程通过 IPC 断开清理仍在运行的 MCP。Compose 开启 `init: true` 回收异常退出后的孤儿进程；直接 `docker run` 应使用 `--init`。

实际运行的 cwd 为 `<data>/workspaces/default/`，连接测试使用 `<data>/workspaces/connection-tests/`。此工作区约定**不是操作系统沙箱**：本地代码仍拥有服务账户的主机权限，必须来自可信来源；不承诺隔离主动逃离进程组的恶意代码。

## 远程 Streamable HTTP MCP

填写 `http://.../mcp` 或 `https://.../mcp` 等完整服务地址，认证放在加密的请求头配置中：

```json
{"Authorization":"Bearer 由管理员填写"}
```

URL 不接受用户信息、查询参数或 fragment，协议保留请求头不可覆盖。地址属于普通配置，敏感值应放请求头。只支持 Streamable HTTP，不提供旧版独立 SSE transport 或 OAuth 授权流程。客户端拒绝重定向，不自动重连或重放工具调用。关闭时尽力向支持会话的服务发送 DELETE，最多等待 1 秒，然后关闭连接；这不等于远程业务操作已撤销。

## 连接、授权和配置快照

1. 保存 MCP 配置前确认可信来源；连接测试可能启动本地程序或连接远程服务。
2. 测试初始化和工具发现，查看工具名称、说明及参数结构。一次测试总连接/发现期限 10 秒，最多同时 4 次，每个服务最多发现 128 个工具。
3. 按工具逐项勾选，仅授予必要权限。写入、删除能力明确提示；“服务声明只读”仅为第三方提供的提示，不能作为强制安全保证。
4. 确认权限后保存助手授权，不增加逐次弹窗。最多关联 20 个 Skills、16 个 MCP 服务、64 个 MCP 工具。

保存连接配置会清空旧工具目录，须重新测试后才能接收使用该服务的新任务。工具目录变化会增加配置版本。任务提交时固定技能指令、资源清单、MCP 连接配置、版本和所选工具定义；凭据另存于加密任务快照，终态后清除。后续配置编辑、撤销授权或删除不改变已接收任务，可另行取消这些任务。

每次运行重新连接所选服务，只注册已授权的工具。MCP 工具使用稳定命名空间，避免不同服务同名冲突；重新发现时若所选工具缺失或参数结构与快照不同，在联系模型前拒绝运行。冻结配置不能锁定外部服务的内部实现或主机程序文件，第三方工具仍需可信并由管理员维护。

Skill 资源和 MCP 返回内容以不可信文本处理，不执行 HTML，不据其指令扩大权限。当前模型链路仅消费文本；非文本 MCP 内容使用类型提示，不转发图片或二进制内容。

删除前会显示关联 Agent 列表并二次确认。删除会清理 Skill 目录或 MCP 配置/密钥，同时自动移除所有 Agent 的关联并递增 Agent revision；已提交任务使用提交时的能力快照，历史运行不受影响。技能详情和 MCP 卡片会反向列出关联 Agent，可直接取消单个关联。

## 超时、取消与记录

沿用运行和工具时限，默认每轮 5 分钟、单工具 60 秒、最多 10 轮工具调用。取消停止后续模型与工具请求，向当前 MCP 请求发送取消并关闭连接，本地进程在资源释放前关闭。远程服务可能继续已发生的操作，不能承诺撤销。

收到明确的 MCP 工具错误时记录失败，模型可以解释该错误；调用连接丢失或结果无法确认时，记录“结果不明”，中断后续执行，不自动重试整个任务或未知操作。Runtime 或平台重启后沿用保守恢复策略，不恢复旧队列或重放调用。

每条回答的“运行详情”展示工具来源、名称和状态。逐项展开“查看调用参数与结果”通过独立鉴权 API 获取业务详情，参数和结果各最多保留约 32 KB，超限明确提示。已知配置凭据在 Runtime 边界进行字面值脱敏；这不意味着工具业务输出中的所有未知秘密都能自动识别。消息正文和工具原始详情不进入普通诊断事件或日志。工具详情与上下文仍是敏感业务数据，需与完整数据目录一同保护和停机备份。

## 本地验证及限制

- Go 测试：可信来源确认、认证、导入副本和文件权限、拒绝符号链接/无效元数据、加密 MCP 配置、请求头与路径校验、工具逐项授权、连接测试结果路由、排队配置与凭据冻结、调用详情与诊断分离、schema 1/2 → 3 迁移。
- Runtime 测试：真实 SDK 的 stdio 初始化/发现、精确环境、工作区、授权工具隔离、成功/明确失败、凭据回传脱敏、工具超时/取消、连接丢失后不重试、Runtime SIGKILL 后清理 MCP 进程及不重放、Skill 限定资源读取、变更工具结构后拒绝运行。Streamable HTTP 使用真实 SDK 服务端验证初始化、认证、工具发现、调用错误、请求取消与会话终止。
- 完整进程 E2E：Go API 配置/测试/关联 → 真实 Runtime 与本地 MCP SDK 服务 → 调用详情、已知密钥脱敏、超时、Runtime 崩溃、外部 effect 不重放及子进程清理。
- Chromium：技能导入、内容/依赖/资源预览、MCP 配置/连接、逐项授权、真实调用详情、密钥不回显和桌面/390px 布局。

以上均使用受控的本地模型与 MCP 测试服务。尚未验证真实模型供应商、第三方 MCP 产品或 Docker 引擎下的部署，不据此公布外部兼容名单。
