# 模型连接配置

在“配置 → 模型连接”中维护连接。左侧选择连接，右侧默认展示连接信息、上下文与输出；推理、采样与兼容选项收在“高级配置”。

## 供应商

每个连接有一个供应商。基础供应商（OpenAI、Anthropic、自定义 OpenAI 兼容网关）始终可用；官方供应商预设来自“Pi 模型供应商”扩展，启用后才会出现在列表中：

| 分组 | 供应商 |
| --- | --- |
| 基础 | OpenAI、Anthropic、自定义 OpenAI 兼容网关 |
| 官方扩展 | OpenRouter、DeepSeek、Groq、Mistral、xAI、Together、Fireworks、Gemini（OpenAI 兼容）、Ollama、vLLM、LM Studio |

启用扩展只在本地记录一条安装状态，不下载或执行第三方代码；它提供的是供应商名称、默认地址和协议。仍有连接使用该扩展时会拒绝停用。选择供应商会自动填入默认地址与协议；切换协议时供应商会跟着切换，避免协议与供应商不一致。未启用扩展的供应商不能保存，已保存但扩展被移除的连接在派发任务时明确失败，不会静默改用其它供应商。连接名称用于识别用途，模型名称仍填写服务商的实际模型 ID。密钥加密保存，编辑时留空保留原值。

## 获取模型列表

模型名称旁的“获取模型列表”使用当前表单中的服务地址、协议与密钥，无需先保存连接或填写模型 ID。已保存连接的密钥留空时，服务端复用该连接的加密密钥；填写新密钥时以当前输入为准。没有鉴权要求的本地服务仍可填写其接受的占位密钥。

OpenAI 两种协议请求基础地址下的 `GET /models`，使用 Bearer 认证；Anthropic 请求 `GET /v1/models`（末尾已有 `/v1` 时不重复），使用 x-api-key 与版本头。读取标准 `data[].id`，去重排序后供下拉选择；仍可切换为手动填写自定义模型 ID。服务不提供列表接口时继续手动填写。

列表仅保留在当前页面内存中，不写入数据库或浏览器持久存储，不修改连接版本。选择 ID 只修改编辑表单，仍需正常保存；切换连接、服务地址、协议或密钥后清空列表，旧请求的迟到响应不会覆盖新配置。模型窗口、输出与推理能力依然需要按实际规格填写。

管理接口为认证及 CSRF 保护的 `POST /api/models/discover`，请求字段 `model_id`（新连接为 0）、`base_url`、`api`、`api_key`；响应为 `{ "models": ["model-id"] }`。服务端最多等待 20 秒、最多读取 2 MiB，不跟随重定向，不返回上游原始错误或密钥，响应禁用缓存。

## 接口协议

| 协议 | 基础地址示例 | 请求接口 |
| --- | --- | --- |
| OpenAI Chat Completions | `https://api.openai.com/v1` | `/chat/completions` |
| OpenAI Responses | `https://api.openai.com/v1` | `/responses` |
| Anthropic Messages | `https://api.anthropic.com` | `/v1/messages` |

填写基础地址，不重复填写请求接口；兼容网关可保留其地址前缀。Anthropic 地址末尾的 `/v1` 会在 SDK 调用前规范化，避免重复路径。协议切换后请检查模型、地址和参数，保存后才能测试；未保存的编辑不会用于连接测试。

连接测试使用对应协议的短文本请求及认证方式，不执行 Agent、不调用工具，不证明供应商所有能力均兼容。实际问答、流式处理与工具交互直接复用锁定的 Pi AI 1.3.0 对应协议适配器，不复制一套 Agent 引擎。该页面不提供 OAuth、云厂商身份认证或任意自定义协议脚本。

## 参数

| 参数 | 用途与限制 |
| --- | --- |
| 上下文窗口 | 模型总窗口，256–10000000 Token，按实际规格填写 |
| 最大输出长度 | 至少 16 Token，必须小于窗口；通过 SDK 传入请求，包含推理消耗 |
| 推理能力与强度 | 仅对支持推理的模型开启；关闭、minimal、low、medium、high，经 SDK 映射为协议参数 |
| Temperature | 可留空；OpenAI 协议 0–2，Anthropic 0–1；Anthropic 开启推理时留空 |
| Top P | OpenAI 协议可配置，须大于 0 且不超过 1；此处不对 Anthropic 发送 |
| 输出长度字段 | 仅 Chat Completions：自动、`max_tokens` 或 `max_completion_tokens`，只在服务商要求时覆盖 |

Anthropic 的预算式推理需要足够输出空间，启用时最大输出至少 2048 Token。各型号是否接受推理和采样参数取决于实际服务；不要仅因网关声称协议兼容而开启能力。

## 上下文保护

以模型配置中的上下文窗口（Token）为依据，Runtime 在每次模型请求前使用 Pi AI 的 `estimateContextTokens` 估算输入，并为配置的最大输出预留空间。SDK 优先使用最近适用的供应商 usage，再估算新增消息；没有 usage 时使用 SDK 的字符与内容估算，包含指令、工具定义与工具结果。它不是供应商的精确 tokenizer，供应商仍可能先拒绝请求；已识别的窗口超限返回新建会话提示。

运行维护中的“上下文保守上限（字节）”已移除。历史保存的 `context_bytes` 接受读取但不再生效，不需要手动提高旧的 24000 字节值。Go 不再把 Token 数当作字节数进行入队判断；模型窗口由持有完整上下文的 Runtime 检查。

平台保留内部 **8 MiB** 会话文本/序列化上下文保护，为内存与私有协议帧预留空间。这是独立的资源保护，不作为模型窗口或普通配置；触发时显示独立的数据量错误。单条输入、工具返回和执行时限仍各自有上限。

上下文选择在 Agent 中配置：最近若干轮、近期时间窗口、自动摘要或完整历史。默认只携带最近 20 轮，窗口不足时按完整轮次裁剪；完整历史策略超限时停止并提示新建会话。自动摘要调用当前模型压缩旧内容，已通过本地压缩、重启和失败路径验证。所有策略都保留平台历史，不重跑整个模型/工具任务，见 [Agent 策略说明](agent-policy.md)。

## 保存、快照与迁移

参数存在 `models.options`，API 字段为 `options`。`PUT` 请求省略它时保留现有参数；显式修改支持按字段合并，采样字段传 `null` 可恢复服务默认值。每次保存增加连接版本；已入队任务保留当时的协议、参数、角色、权限及独立凭据，修改只影响之后提交的任务。

模型参数在 schema **8** 引入；供应商在 schema **15** 引入，旧连接按协议映射为 OpenAI 或 Anthropic。当前 schema **22** 从 1–21 自动迁移。旧连接采用旧运行层已有的 Chat Completions、32768 上下文、4096 输出、无推理默认值，保留原密钥与连接版本。升级前停机备份整个数据目录；旧版程序不能直接打开新数据库，回退需恢复完整旧备份。

Go 测试覆盖验证、旧客户端保留参数、排队冻结、三种协议探针和旧版迁移；Runtime 测试用本地 HTTP/SSE 服务验证三个原生适配器的文本、认证、输出、采样/推理参数及输入预算、超过旧字节上限的长输入和独立资源保护。浏览器验证协议专属控件、密钥不回显、保存/测试、真实 Go/Node 请求参数及桌面/移动布局。真实供应商兼容性须另行验收。
