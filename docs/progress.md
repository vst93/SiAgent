## 渠道入站图片

- [x] 渠道图片接收：新增协议字段 `Incoming.images` 与适配器能力 `images`。企微智能机器人的 worker 用官方 SDK 下载并用消息自带的 AES 密钥解密图片，只把暂存文件名写进私有协议，图片不进入 256 KiB 的协议帧。
- [x] 平台媒体链路：schema 28 为 `channel_inbox` 增加 `attachments`。平台按内容检测图片格式，套用与 Web 附件相同的单张 4 MiB、单条 5 MiB、最多 8 张及每会话上限；通过校验后暂存在 `<data>/channel-media/<channel>/staged/`，准入时转成该会话的普通对话附件。因此模型按 image content block 收到，管理后台会话历史直接显示图片。
- [x] 拒绝路径：适配器不支持图片、Agent 关闭图片开关、模型未声明图片输入、格式/大小超限时都记为 `rejected` 并给出具体文字说明，不创建任务；适配器上传文件总会被消费或删除，不会留在磁盘。
- [x] 去重与重试：入站指纹按图片内容（而非每次不同的暂存文件名）计算，同一 MsgId 携带不同图片视为冲突；重复投递幂等，不重复上传。准入被延后（如运行服务未就绪）时保留已提升的附件 ID，重试不会产生第二份图片。
- [x] Agent 配置项：新增 `session.images`（默认开启）与“会话限制 → 允许渠道成员发送图片”；Web 附件仍只受模型图片输入开关控制。
- [x] 清理：服务启动与渠道归档时清除适配器上传区与暂存区；拒绝或延后消息不会留下孤儿文件。
- [x] 测试：Go 覆盖端到端图片准入与模型下发、无视觉模型/关闭开关/文本适配器拒绝、超限与非图片内容、路径穿越、重放冲突与幂等、延后准入不丢图片、启动与归档清理，以及一个真实 Node 进程适配器经由进程协议暂存图片的完整链路。Runtime 测试覆盖 worker 下载并暂存、图文混排、下载失败降级与语音转写。

## 企微响应速度、渠道流式输出与 Agent 环境变量

- [x] 企微收到消息后立即确认：新增出站类型 `ack`。仅对声明 `streaming` 的适配器（企微智能机器人）在入站落盘时排入“已收到，正在作答”，与最终回答共用同一 `stream.id`，不增加消息条数；自建应用等旧适配器保持原 30/90 秒提示逻辑。
- [x] 渠道作答进度：`message_delta` 落盘后按约 1.5 秒间隔、内容确有增长时更新同一条流式消息（新增出站类型 `draft`，按适配器字节上限截断、不拆分），完成时用完整回答覆盖；最终回复产生时取消尚未发送的确认与草稿。已输出作答进度时不再发送 90 秒“仍在处理”提示。
- [x] 企微流式限制：以 9 分钟为界切换新的流式消息，避免更新已超过厂商 10 分钟上限的消息；最终回复才 `finish=true`，其余中间内容 `finish=false`。
- [x] 思考标签兼容：新增 Agent 输出配置 `think_tags`（`strip` 默认 / `keep`），Runtime 与平台均剔除 `<think>`、`<thinking>`、`<reasoning>`、`<reflection>` 等标签（支持属性和大小写、跨 delta 拆分），剔除内容在开启思考时作为思考摘要；`keep` 完全保留原文。
- [x] 思考摘要长度：新增 `thinking_max_chars`（默认 1200，200–8000），只限制渠道回复中的摘要长度，超出截断并提示；Web 与运行详情仍保留 64000 字符。
- [x] 渠道确认与流式开关：新增 `acknowledge`、`stream`（默认开启），三个回复预设同步设置；关闭后只发送最终回复。
- [x] Agent 系统环境变量：schema 26 增加加密的 `agents.environment`；API 只返回 `env_keys`，保存接受 `env`（空值保留）与 `env_remove`，改动只审计变量名；变量在提交时随凭据快照冻结，只注入该助手工作区命令的 `bash` 环境，模型仅看到变量名，工具输出/思考/回答中的同名值脱敏。
- [x] Go 测试覆盖：即时确认先于任务、草稿与最终回复共用一条消息、进度后不再发提示、关闭流式只发最终回复、think 标签剔除与摘要截断、环境变量加密/冻结/下发/校验/审计及旧适配器行为。Runtime 测试覆盖 think 标签跨 delta 剔除与 `keep`、环境变量注入 `bash` 与脱敏；企微 Worker 测试覆盖 `ack`/`draft` 不结束流、9 分钟窗口切换和超长拒发。

## 应用内更新修复：暂存安装与服务模式重启

- [x] 修复暂存安装误注册用户服务：更新下载阶段调用安装脚本时缺少 `--no-service`，安装脚本会用自己的临时前缀覆盖 `systemd`/`launchd` 服务单元并立即重启，导致新进程从 `.update-*` 暂存目录启动、数据目录变成 `stage/data`（等同全新安装），且更新完成后服务单元指向已删除的路径。现在暂存安装固定 `--no-service`，并新增参数回归测试。
- [x] 修复服务模式就绪校验永不匹配：`systemctl restart`/`launchctl kickstart -k` 无法传递 `SIAGENT_UPDATE_BOOT`，90 秒后必然判定失败。启动标识改为写入安装目录 `.update-boot`，新进程启动时读取并删除，再经 `/health/ready` 回传；无标识时降级为仅校验版本。
- [x] 服务模式回滚先停止失败的新服务并等待数据锁释放，再用 `start` 拉起旧版本；此前失败进程仍占用数据锁，回滚无法执行。
- [x] `waitReady`、启动标识单次消费、暂存安装参数均有 Go 测试覆盖。
